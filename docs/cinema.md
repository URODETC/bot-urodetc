# Кино: RuTracker → qBittorrent

## Настройка

Сервис использует существующий qBittorrent. Включите его WebUI и создайте категорию
`cinema`. Бот и воркер должны иметь доступ к адресу WebUI. В Docker `localhost`
обозначает текущий контейнер; укажите адрес сервиса или хоста qBittorrent.

Заполните в `.env` переменные из `.env.example`:

- `OWNER_TELEGRAM_IDS`: кто может искать и скачивать.
- `RUTRACKER_URL`: HTTPS-адрес RuTracker без `/forum`.
- `RUTRACKER_USERNAME`, `RUTRACKER_PASSWORD`: учётная запись RuTracker.
- `RUTRACKER_SESSION`: необязательное значение cookie `bb_session`.
  Если RuTracker требует CAPTCHA, войдите вручную в браузере и задайте cookie
  вместо логина/пароля. При истечении сессии обновите её и перезапустите воркер.
- `QBITTORRENT_URL`, `QBITTORRENT_USERNAME`, `QBITTORRENT_PASSWORD`: WebUI клиента.
- `QBITTORRENT_SAVE_PATH`: путь внутри qBittorrent; файлы остаются там.
  При пустом значении используется стандартный путь клиента.
- `QBITTORRENT_CATEGORY`: категория (по умолчанию `cinema`).

Секреты задаются только в окружении, не в Telegram. Окружение должно совпадать
у процессов бота и воркера. Не публикуйте WebUI в интернет ради подключения бота.

Запуск через существующий Compose:

```sh
docker compose up -d --build bot worker
```

Таблица `service_jobs` создаётся при старте приложения. Для очереди нужен запущенный
общий ARQ-воркер (`app.tools.video.worker.WorkerSettings`) и существующий Redis.
Файлы кино не проходят через Telegram и не ограничиваются его размером вложений.

## Использование

```text
/cinema Дюна 2021
/cinema Во все тяжкие сезон 2
/cinema хочу посмотреть фильм Интерстеллар 2014
/cinema_status
```

Поиск асинхронный. Бот присылает до 50 отсортированных вариантов, по пять на странице.
«Описание» открывает страницу раздачи, «Скачать» создаёт задачу передачи magnet-ссылки
в qBittorrent. После приёма клиентом и завершения загрузки бот отправляет сообщения.
`/cinema_status` показывает последние пять задач и кнопки возврата к результатам поиска; прогресс обновляется примерно раз
в 30 секунд, при загруженном воркере реже.

Сначала отбрасываются несовпадающие название, год и сезон. У доступных раздач
приоритет: разрешение (2160p выше 1080p), указанная озвучка, число сидов, источник.
Раздачи без сидов идут в конце. HDR и Dolby Vision выводятся как свойства,
но автоматически не предпочитаются: совместимость зависит от устройства.
Озвучка определяется по меткам Dub/MVO/DVO/AVO в заголовке; это не гарантия наличия
русской дорожки. Перед выбором можно проверить описание.

Повторное нажатие той же кнопки не создаёт новую задачу. Уже имеющийся в qBittorrent
infohash повторно не добавляется. Сервис не меняет состояние существующей раздачи:
если она остановлена, возобновите её в клиенте. Для повторной попытки после ошибки
запустите новый поиск. Кнопки результатов действуют сутки.

## Границы первой версии

- Это поиск по названию, а не рекомендательная модель. Запросы по сюжету,
  автоматический перевод названия, исправление опечаток и каталог метаданных
  пока не реализованы. Год лучше указывать для одноимённых фильмов.
- Сначала выполняется отдельный запрос на 2160p, затем общий поиск по названию.
  Поиск ограничен первыми страницами RuTracker; он не гарантирует обнаружение
  всех раздач. При широком запросе уточните название.
- Парсер сезонов понимает `Сезон: 2`, `S02`, диапазоны `Сезоны: 1-3`.
  Выбор отдельных файлов/эпизодов внутри раздачи и подписки на новые серии
  не реализованы. Скачивается вся выбранная раздача.
- У RuTracker нет используемого здесь стабильного публичного API: HTML может
  измениться. CAPTCHA и недоступность сайта требуют действий владельца.
- Задачи и их прогресс сохраняются в БД. Выдача заданий — с возможным повтором:
  просроченная пятиминутная аренда позволяет восстановиться после падения воркера.
  Временные ошибки повторяются до трёх раз; успешная операция сбрасывает счётчик.
  Уведомления Telegram пока отправляются без отдельной долговечной очереди:
  при недоступности Telegram сообщение может быть пропущено.
- Автоматическая очистка истории, переименование медиатеки, управление местом
  на диске и интеграция с Plex/Jellyfin пока отсутствуют.

## Архитектура и проверки

`CinemaTool` зарегистрирован в общем реестре. `CinemaService` не зависит от Telegram:
он работает с абстракциями `TrackerProvider` и `DownloadProvider`. HTML и HTTP
изолированы в конкретных провайдерах. Очередь `app/jobs/persistent.py` хранит
тип, полезную нагрузку, результат, владельца, статус и аренду задания. Общий
ARQ-воркер подбирает готовые задачи каждые пять секунд. Скачивание выполняет
qBittorrent; воркер только добавляет раздачу и опрашивает прогресс.

```sh
uv run python -m unittest discover -s tests -v
```

Тесты используют синтетическую HTML-страницу, HTTP-заглушки и SQLite. Живое
подключение к аккаунту RuTracker и qBittorrent нужно проверить после настройки.
